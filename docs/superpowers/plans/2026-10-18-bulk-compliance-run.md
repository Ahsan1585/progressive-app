# Bulk Compliance Analysis & Auto-Generate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a billing specialist bulk-select practitioners (or "select all") within one chosen billing period and run compliance analysis across all of them in one action. A practitioner whose entire selected period is clean (every session matched, unflagged, no duplicate) automatically generates its SEVF + invoice and moves to Completed Bills. A practitioner with any flag is left untouched in Pending Bills for manual review, exactly as today.

**Architecture:** Extract the existing single-practitioner compliance-matching logic (`getComplianceAnalysis`), lock acquire/release (`lockPractitioner`/`unlockPractitioner`), and the two generate steps (`generateNJEISForms`/`generateFinancialInvoice`) into internal, reusable functions callable both by their existing HTTP handlers (unchanged behavior/response shape) and a new `POST /api/billing/bulk-compliance-run` endpoint that loops over selected practitioners, lock-check/acquire/release per practitioner, and either auto-generates or leaves them for manual review. Frontend adds practitioner-queue checkboxes + a "Run Compliance Analysis (N selected)" bar to `BillingBatchReview.jsx`, reusing the Set-based multi-select pattern already used in `RegisterPractitionerForm.jsx`.

**Tech Stack:** Node/Express (CommonJS), PostgreSQL via `pg` (tenant-scoped `pool.query` through `AsyncLocalStorage` — no explicit tenant filtering needed), React (no TypeScript in this codebase), Tailwind CSS, `pdf-lib` for PDF generation, GCS for file storage.

**Spec:** `docs/superpowers/specs/2026-10-18-bulk-compliance-run-design.md`

## Global Constraints

- One batch = one practitioner × one date range (unchanged) — `billing_batches.practitioner_id` stays a single integer FK. No schema change to that table.
- "All-or-nothing clean" is scoped to the exact `startDate`/`endDate` period passed to the bulk endpoint — never a practitioner's full backlog across other periods.
- A practitioner already locked (by a human or another bulk run) is silently skipped — never blocks the rest of the batch, never errors the whole request.
- The bulk run acquires the `review` scope lock on a practitioner immediately before processing them and releases it immediately after (whether auto-generated or left for review) — never holds all selected practitioners' locks for the whole run.
- "Clean" for auto-generate = every session in the period is `matched === true`, `flagged === false`, and has no `duplicateOfSessionId` — strictly matches `getComplianceAnalysis`'s per-session result shape.
- `documentOnFile === false` (no compliance reference document, or no mapping confirmed) means NO practitioner in the run can be "clean" — every selected practitioner goes to `needsReview` in that case (there's nothing to compare against). Existing single-practitioner behavior for a missing document is unchanged.
- The existing single-practitioner Compliance Analysis tab, Generate & Issue buttons, and lock/unlock buttons must behave byte-for-byte identically after the extraction refactor — this is a reuse refactor, not a rewrite of their behavior.
- Every new/modified backend function stays inside `backend/src/controllers/billingController.js` (where all the logic it reuses already lives) — no new controller file for this feature.
- Route guard: reuse the existing `pendingGuard` (`protect, loadPermissions, requirePermission('billing_pending')`) for the new endpoint — same permission as every other Pending Bills action.

## Review Focus

- **Zero sessions in the selected period for a selected practitioner** — the practitioner has no sessions with `service_date` in `[startDate, endDate]` at all (e.g. selected by mistake, or their only sessions are outside this period). Expected: skipped with a `no_sessions` outcome, not an error, not silently treated as "clean" (an empty set must never auto-generate).
- **A practitioner mid-split (two cards: "Needs review" + "Sent to billing")** — some of their sessions in the period are already `njeis_review`/`invoiced`/`completed` from an earlier manual Generate & Issue. Expected: the bulk run's "clean" check only considers sessions still eligible for generation (`billing_status = 'pending'`, matching what `generateNJEISForms`/`generateFinancialInvoice` actually select) — it must not re-flag or re-process already-generated sessions, and must not count them against "needs review" either.
- **`practitionerIds: 'all'` on a period where zero practitioners have any pending logs** — expected: a clean `{autoGenerated: [], needsReview: [], skippedLocked: [], noSessions: []}` response, not a 400/500.
- **Concurrent bulk runs selecting overlapping practitioner sets** — two billing specialists both click "Select all" and run at nearly the same time. Expected: per-practitioner lock acquisition means each practitioner is processed by exactly one of the two runs; the other sees it in `skippedLocked`. Covered by Task 5's row-level lock test plus Task 7's integration test.
- **`generateNJEISForms` succeeds but `generateFinancialInvoice` fails for a "clean" practitioner mid-auto-generate** — expected: same partial-failure shape the manual flow already has today (SEVF exists, invoice doesn't; `readyToComplete` stays false) — the bulk run must not crash the whole batch over one practitioner's partial failure, and must still report `autoGenerated` only once BOTH documents exist (covered by Task 4's test for `runAutoGenerateForPractitioner`'s error handling, and Task 6 ensures the bulk loop continues past a per-practitioner exception).

```js
async function acquireLock(practitionerId, lockerId, scope = 'review') {
  const { rows: insertedRows } = await pool.query(
    `INSERT INTO billing_locks (practitioner_id, lock_scope, locked_by)
     VALUES ($1, $2, $3)
     ON CONFLICT (practitioner_id, lock_scope) DO NOTHING
     RETURNING practitioner_id`,
    [practitionerId, scope, lockerId]
  );
  if (insertedRows.length > 0) return { acquired: true };

  const { rows: existingRows } = await pool.query(
    `SELECT bl.locked_by, p.first_name, p.last_name
     FROM billing_locks bl JOIN practitioners p ON p.id = bl.locked_by
     WHERE bl.practitioner_id = $1 AND bl.lock_scope = $2`,
    [practitionerId, scope]
  );
  const existing = existingRows[0];
  if (existing?.locked_by === lockerId) return { acquired: true, alreadyMine: true };
  const lockedByName = `${existing?.first_name || ''} ${existing?.last_name || ''}`.trim();
  return { acquired: false, lockedByName };
}

async function releaseLock(practitionerId, scope = 'review') {
  await pool.query('DELETE FROM billing_locks WHERE practitioner_id = $1 AND lock_scope = $2', [practitionerId, scope]);
}
```

```js
const bulkComplianceRun = async (req, res) => {
  const { practitionerIds, startDate, endDate } = req.body;
  if (!startDate || !endDate) {
    return res.status(400).json({ error: 'startDate and endDate are required' });
  }

  try {
    let targetIds;
    if (practitionerIds === 'all') {
      const { rows } = await pool.query(
        `SELECT DISTINCT practitioner_id FROM assessments
         WHERE billing_status = 'pending' AND service_date >= $1 AND service_date <= $2`,
        [startDate, endDate]
      );
      targetIds = rows.map((r) => r.practitioner_id);
    } else if (Array.isArray(practitionerIds)) {
      targetIds = practitionerIds;
    } else {
      return res.status(400).json({ error: 'practitionerIds must be an array of ids or the string "all"' });
    }

    const autoGenerated = [];
    const needsReview = [];
    const skippedLocked = [];
    const noSessions = [];

    for (const practitionerId of targetIds) {
      const { rows: nameRows } = await pool.query(
        'SELECT first_name, last_name FROM practitioners WHERE id = $1', [practitionerId]
      );
      const name = nameRows[0] ? `${nameRows[0].first_name} ${nameRows[0].last_name}`.trim() : 'Unknown';

      const lockResult = await acquireLock(practitionerId, req.practitioner.practitionerId, 'review');
      if (!lockResult.acquired) {
        skippedLocked.push({ practitionerId, name, lockedByName: lockResult.lockedByName });
        continue;
      }

      try {
        const { rows: pendingCountRows } = await pool.query(
          `SELECT COUNT(*)::int AS count FROM assessments
           WHERE practitioner_id = $1 AND billing_status = 'pending'
             AND service_date >= $2 AND service_date <= $3`,
          [practitionerId, startDate, endDate]
        );
        if (pendingCountRows[0].count === 0) {
          noSessions.push({ practitionerId, name });
          continue;
        }

        const analysis = await runComplianceAnalysisForPractitioner(practitionerId, startDate, endDate);
        const resultValues = Object.values(analysis.results);
        const isClean = analysis.documentOnFile
          && resultValues.length > 0
          && resultValues.every((r) => r.matched === true && r.flagged === false && !r.duplicateOfSessionId);

        if (isClean) {
          const generated = await runAutoGenerateForPractitioner(practitionerId, startDate, endDate, req.practitioner.practitionerId);
          autoGenerated.push({ practitionerId, name, batchId: generated.batchId });
        } else {
          needsReview.push({ practitionerId, name });
        }
      } catch (perPractitionerError) {
        console.error(`bulkComplianceRun: failed for practitioner ${practitionerId}:`, perPractitionerError);
        needsReview.push({ practitionerId, name });
      } finally {
        await releaseLock(practitionerId, 'review');
      }
    }

    logAudit({
      req, action: 'bulk_compliance_run', resourceType: 'billing_batch', resourceId: null,
      details: { startDate, endDate, autoGeneratedCount: autoGenerated.length, needsReviewCount: needsReview.length, skippedLockedCount: skippedLocked.length },
    });
    res.json({ success: true, autoGenerated, needsReview, skippedLocked, noSessions });
  } catch (error) {
    console.error('bulkComplianceRun error:', error);
    res.status(500).json({ success: false, error: 'Failed to run bulk compliance analysis' });
  }
};
```
